# review-widget composition manifest — public/marketing-hub/

Composed 2026-10-27 (MH-95). Operator: "add the commenting / review module to the marketing hub. You can find specs for it
in the library and it has been applied to other projects in the project folder." Base: the Credo `harassment-lp`
composition (pinned 1.3.0: comment-status-indicators, global-comment-list with the This page / All pages toggle).
Loaded from `app.html` after `gate.js`: `review.config.js`, `review-bootstrap.js`. Inert without `?review=1` (one floating
"Comments" button); with it, `review-mode.css` + `review-mode.js` load and comments go to Firebase `credo-712c4` `/comments`.

## Operator decisions (27 Oct 2026)
- **No text preview stored.** The database is readable without the hub password; hub screens hold client material. A record
  is `{comment, replacement, anchor, page, drawer?, author, status, timestamp}` (+ edited_at / resolution / resolved_at /
  resolved_by from the lifecycle). The composer shows the element's text live; it is not saved.
- **Comment scope = route + tab.** `page` = `credo-marketing-hub:<hash route>[?tab=<tab>]`.

## Deviations from 1.3.0 (hash-routed single-page app) — backport candidate "hash-route screens"
1. **Screens instead of pathname pages.** `pageSlug()` is replaced by `screenKey()` from `location.hash` (path + `?tab`),
   re-read on every pass, on `hashchange` and every 400 ms (the hub changes the hash with `history.replaceState` when a
   drawer opens, which fires no event).
2. **Drawers.** A comment left inside a drawer stores `drawer` = `d=<item>&dt=<tab>` (the hub's MH-79 drawer permalink). It
   decorates only while that drawer is open on that tab; in the list it shows a drawer chip and "opens ↗" otherwise.
3. **Deterministic, per-root anchors** (replaces the sticky counter of anchor-extensibility for this surface). Each pass
   renumbers each root afresh in document order: `m-` main panel, `d-` right drawer, `l-` search-terms drawer. The same
   screen always yields the same ids however the reviewer arrived. Side navigation, top bar and the password gate are chrome.
4. **Cross-screen jump without reload.** global-comment-list's focus handoff sets the hash (with d/dt for drawer comments);
   the hub renders the screen / opens the drawer, and the widget spotlights the anchor (retries up to ~3 s).
5. **"All screens" = this hub only** (records whose page starts with the hub prefix); the other Credo hubs' records, the
   drawer "Comments" tab records (page `credo-marketing-hub`) and organic approvals (`organic-approval`) are not listed.
6. **Layout.** Banner 46 px + sidebar 330 px: the hub's body pads right by the sidebar width, its drawers move below the
   banner and left of the sidebar; a banner button hides / shows the sidebar (hidden by default under 900 px).
7. **Outlines.** The faint dashed outline shows on hover only, and `position:relative` applies only to commented elements
   (a blanket relative would undo the hub's sticky headers).
8. **Not composed:** variant-anchors, cross-page-slot-comments, the live-page chip (landing-page features), click-to-reveal.

## Verified (27 Oct 2026, local, writes kept in the test browser)
Inert path (button only, no widget files requested, no anchors); review mode (406 anchors on the Stream 2 page, none in
navigation / bar); add → record shape above; indicator outline + dot; another screen → 0 rows on "This screen", 1 on "All
screens" grouped by screen; jump back → same hash, spotlighted anchor; fresh load → same anchor id; drawer comment → record
with `drawer`; drawer left of the sidebar (right edge 1170 = sidebar left 1170); close drawer → "opens ↗" → drawer reopens and
spotlights; resolve with note; hide sidebar → full width; phone 390 px → sidebar hidden, no horizontal scroll; no page errors.
Cost: one anchor pass ≈ 3–17 ms on typical screens, ≈ 110 ms on Search terms (32k elements), only when the DOM changes.
